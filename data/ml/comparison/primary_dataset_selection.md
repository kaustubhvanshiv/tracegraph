cle# Primary Dataset Selection — TraceGraph ML/GNN Research

## Selected Dataset

**DARPA Transparent Computing Engagement 5 (TC E5)**

Local path: `../datasets/Darpa/`

---

## Selection Rationale

### 1. Graph Constructibility

DARPA TC E5 is the only candidate that can produce a multi-typed provenance graph. Its CDM schema provides all six TraceGraph entity types (User, Host, Server, Process, File, IP) as first-class node records, and its `Event` records carry enough information to derive all five TraceGraph relationship types. The other candidates are structurally limited: LANL produces a User–Host–Process subgraph with no File nodes; UNSW-NB15 and CIC-IDS2017 reduce to flat IP-to-IP multigraphs.

The CDM schema maps directly to the Neo4j node/relationship model that TraceGraph already uses. Entity deduplication, process lineage, and file-access subgraphs are all constructible in a single pass over the Avro streams.

### 2. Ground Truth Quality

Ground truth is provided as a PDF narrative (`TA51_Final_report_E5.pdf`) describing multi-stage attack scenarios per host and time window. It has no machine-readable per-record label, which means attack/benign annotation requires aligning `Event.timestampNanos` and `TCCDMDatum.hostId` against the narrative document.

This is a significant labelling overhead compared to UNSW-NB15 and CIC-IDS2017, which carry per-row labels. However, the DARPA ground truth reflects genuine multi-stage APT activity — Firefox Drakon exploitation, Mimikatz credential harvesting, BITS micro-APT, C2 communication, Nginx exploitation, SSH/SCP lateral movement — rather than synthetic testbed traffic. The scenarios are directly analogous to the investigation model TraceGraph is designed to support.

UNSW-NB15 and CIC-IDS2017 offer denser per-row labels, but both were generated by scripted attack tools against closed testbeds and are known to contain label noise and statistical artefacts that make classification artificially easier than real-world detection (Kenyon et al., 2020; Engelen et al., IEEE TNSM 2021). LANL's 749 red-team labels cover only authentication events and represent 0.000071% of its 1.05-billion-record auth file.

### 3. Event / Row Semantics

Each CDM `Event` record is a discrete, timestamped, typed system-level event. The `Event.type` enum has 58 values covering process lifecycle, file I/O, network activity, authentication, IPC, and module loading. This is the only candidate where rows carry a discrete semantic action that maps directly to TraceGraph's `SecurityEvent.action` field.

LANL records are partially typed (auth orientation and process Start/End), but DNS lookups and network flows carry no explicit action. UNSW-NB15 and CIC-IDS2017 are aggregated flow statistics — each row is a pre-computed summary of a completed connection with no discrete action field at all.

### 4. Relationship Information

DARPA TC E5 supports all five TraceGraph relationship types: LOGGED_INTO, AUTHENTICATED_TO, EXECUTED, CONNECTED_TO, and ACCESSED. The `action` field required for relationship extraction is derivable from `Event.type` for each type.

LANL supports four of five relationship types for auth and process events, but ACCESSED is not constructible due to absent file events. UNSW-NB15 and CIC-IDS2017 support only CONNECTED_TO, and even that cannot be derived from an explicit action field — it must be inferred from the fact that a flow record exists.

### 5. SecurityEvent Compatibility

The CDM schema populates the most fields of TraceGraph's `SecurityEvent` model:

- `event_id`: `Event.uuid` — globally unique, non-empty.
- `timestamp`: `Event.timestampNanos` — nanosecond UTC; converts to UTC-aware datetime without an epoch offset.
- `event_type` and `action`: derived from the `Event.type` 58-value enum.
- `source_host`: `Host.hostName` linked via `TCCDMDatum.hostId`.
- `source_ip` / `destination_ip`: `NetFlowObject.localAddress` / `remoteAddress`.
- `process`: `Subject.cmdLine` (optional but present when populated).
- `file`: `Event.predicateObjectPath` (optional; path is on the Event record, not the FileObject).
- `user`: `Principal.username` (optional) or `Principal.userId`.

Several fields are optional in CDM and have stream-dependent population rates. Actual rates must be assessed during Avro deserialization. This is a known uncertainty, not a structural gap.

The flow-oriented datasets cannot populate `event_type`, `action`, `source_host`, `process`, or `file` at all. LANL populates `user` and `source_host` only with anonymised identifiers that carry no semantic meaning outside the dataset.

### 6. Investigation / Attack-Scenario Suitability

DARPA TC E5 contains five distinct multi-stage attack scenarios spanning both the CADETS (FreeBSD) and FiveDirections (Windows) streams. Each scenario involves multiple techniques across multiple hosts — web server exploitation leading to lateral movement, credential harvesting, and C2 exfiltration. These directly model the investigation pattern TraceGraph is designed for: a named investigation with a bounded set of events, extracted entities, correlated relationships, and a narrative summary.

No other candidate provides this structure. LANL's 749 red-team markers are individual authentication hop events without documented campaign structure. UNSW-NB15 and CIC-IDS2017 contain isolated attack flows, not multi-stage campaigns.

### 7. Leakage Risk

The primary leakage risk for DARPA TC E5 is stream-identity leakage: a model that learns OS-level differences between the FreeBSD CADETS stream and the Windows FiveDirections stream, rather than attack-behaviour patterns. This is mitigated by treating streams as separate evaluation partitions.

CADETS has duplicate records from a topic rename (deduplication by `Event.uuid` + `Event.sequence` is required) and publishing gaps from 2019-05-08 to 2019-05-09. FiveDirections has host restarts that sever `Subject.parentSubject` UUID chains. Both issues are solvable with preprocessing.

UNSW-NB15 and CIC-IDS2017 carry IP-based memorisation risk from small fixed testbed topologies, and both have had their ground-truth labelling methodology criticised for producing label noise from post-hoc IP/time-window matching.

### 8. Dataset Limitations and Biases

The following limitations are accepted as part of the selection:

- **No machine-readable per-record labels.** Annotation from the ground-truth PDF is a prerequisite for supervised learning. This is a one-time labelling effort, not an ongoing constraint.
- **Binary Avro format.** All processing requires the `TCCDMDatum.avsc` schema and an Avro deserializer (`fastavro` in Python). Raw data cannot be inspected with standard CSV tooling.
- **Only two TA1 streams locally.** THEIA, MARPLE, and ClearScope data are absent. This limits the attack scenario coverage to CADETS (FreeBSD) and FiveDirections (Windows) scenarios only.
- **Optional CDM fields.** `cmdLine`, `predicateObjectPath`, `parentSubject`, and `username` are optional. Actual population rates are unknown without deserialization and must be measured before feature engineering decisions are made.
- **Controlled lab environment.** DARPA TC datasets have been criticised for stereotyped attack patterns relative to real APT activity. This is a known bias shared by all four candidates — UNSW-NB15 and CIC-IDS2017 are also lab-generated.
- **Access restriction.** DARPA TC data requires programme affiliation. The dataset cannot be redistributed, which limits external reproducibility.

### 9. Computational Feasibility

The two CADETS and three FiveDirections `.bin` files total approximately 11.9 GB of raw Avro data. Processing requires full deserialization — record counts cannot be estimated without it. This is a higher upfront engineering cost than loading a CSV, but within reach of a standard workstation with a streaming Avro reader.

The deserialization pipeline is a one-time preprocessing step. Once events are extracted to a structured format (e.g., Parquet or a local database), all subsequent ML and graph-construction work operates on the extracted data. UNSW-NB15 and CIC-IDS2017 are immediately memory-feasible at 759 MB and 1.2 GB respectively, but their structural incompatibility with the TraceGraph entity model makes that convenience irrelevant for this research context.

### 10. Licensing and Usage Constraints

DARPA TC E5 was distributed under a DARPA research programme. Access required programme affiliation at the time of distribution. The data must not be redistributed. Citation and attribution are expected in any publications using this dataset.

LANL data is available under the LANL open data policy for research use (attribution required; no commercial redistribution). UNSW-NB15 and CIC-IDS2017 are available for academic research use with attribution. None of the four datasets permit commercial redistribution.

## Rejected Candidates — Summary

**D2 LANL:** Acceptable as a secondary benchmark for auth-graph experiments (verified per-event labels, real enterprise environment, structured auth semantics). Not selected as primary because: full anonymisation of all identifiers (no IP addresses, no real process names), no File events, no process hierarchy, and 749 attack labels covering only auth events at an extreme class ratio of 0.000071%.

**D3 UNSW-NB15 and D4 CIC-IDS2017:** Structurally incompatible with the TraceGraph entity-relationship model. Neither dataset can populate the `action` field required for relationship extraction. Neither supports more than one of the five TraceGraph relationship types. Neither produces any entity type beyond IP. Both were generated by scripted tools in closed testbed environments and carry known label noise. They are appropriate for conventional network intrusion detection benchmarks but not for research grounded in the TraceGraph provenance graph.
